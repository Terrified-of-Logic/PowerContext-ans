# 一页技术说明

## 一、模块结构

```
任务描述
   │
   ▼
┌─────────────────────────────────────────────────────┐
│ 上下文模块  context/cli.mjs                          │
│   ingest ──► 切分 ──► seekdb(ctx_docs, 22 条)        │
│   context ─► 检索 ─┬─► 规格条目（行为依据）           │
│                    ├─► 代码文件与符号（改哪里）       │
│                    ├─► 测试用例（怎么验证）           │
│                    └─► PowerContext 任务状态（做到哪了）│
└─────────────────────────────────────────────────────┘
   │  组装成 Markdown 上下文
   ▼
MiniMax（MiniMax-Text-01）  ──►  整文件代码
   │
   ▼
业务工程 business/src/orders.js  ──►  跑测试  ──►  结果写回 PowerContext
```

## 二、上下文选择方式

**切分**：按资料类型采用不同策略，因为三类资料结构不同。

| 类型 | 切分单位 | 理由 |
|---|---|---|
| 规格 `specs/*.md` | 按 Markdown 标题（`##` / `###`） | 一个条目就是一条需求，粒度与「遵守哪些要求」对齐 |
| 代码 `src/*.js` | 整文件，并提取导出符号名 | 一次改动通常落在一个文件内；符号名用于定位「改哪里」 |
| 测试 `test/*.js` | 按 `test('...')` 块 | 一个条目就是一条用例，能直接对应「用哪些测试验证」 |

**打分**：中英文混合分词（英文按词、中文按 2-gram），三处加权——

```
score = Σ( 正文命中 + 标题命中×4 + 符号命中×4 )
规格条目再乘 1.4            # 规格是行为的唯一依据，优先给
```

**兜底**：某类资料得分为 0 时，回退到该类型的全部条目，保证输出不会缺少某一类来源。

**为什么不用向量检索**：语料在百条量级，关键词 + 结构打分已经足够准（实测
「实现按状态过滤」能精确命中 `R1 按状态过滤`、`src/orders.js`、对应的三条测试）。
上万条语料时应换成 seekdb 的 `VECTOR` 列 + HNSW 索引——本仓库另一题的实现已经验证过这条路。

## 三、三项技术的分工

| 技术 | 承担的作用 | 具体调用 |
|---|---|---|
| **MiniMax** | 唯一负责写代码的角色 | `chatcompletion_v2`，输入上下文+任务，输出整文件代码，本次 1382 tokens / 15.7 s |
| **seekdb** | 工程资料的**唯一事实来源** | 22 条规格/代码/测试写入 `ctx_docs`，每次构造上下文都从库里检索；规格改了重新导入，输出随即改变 |
| **PowerContext** | 任务进度的**跨会话载体** | 每轮任务结束写入一条 `state`，下次构造上下文时读回并附在「四、任务当前状态」 |

三者的边界很清楚：

- seekdb 回答「**当前有效的要求是什么**」——它管的是工程事实
- PowerContext 回答「**这个任务做到哪了**」——它管的是工作状态
- MiniMax 只消费前两者的输出，不自己去找资料

这个分工让「规格变更」和「任务中断」两件事都有了着落：规格变了，重新 `ingest` 即可；
任务断了，PowerContext 里的记录能把上下文接上。

## 四、可验证性

六个验收点都有可直接执行的证据，见 `docs/验证样例.md`：

| 验收点 | 证据 |
|---|---|
| 能运行 | `ingest` / `context` / `stats` / 测试 四条命令均无需额外依赖即可执行 |
| MiniMax 实际参与 | `agent/runs/*/response.md` 与 `patched-orders.js`，与 `orders.before.js` 有差异 |
| 上下文正确 | `context.md` 三部分来源齐全；规格更新后输出跟随变化 |
| 数据库实际参与 | `stats` 显示 22 条；删掉 `context/data` 后检索为空，重新 ingest 后恢复 |
| 状态可复用 | 重启 PowerContext 服务后 `entries/list` 仍返回原记录 |
| 代码修改有效 | 改前 `pass 9 / fail 2`，改后 `pass 11 / fail 0`，9 条回归用例全程通过 |

## 五、局限

- 只支持 `.md` 与 `.js`，其他语言需补切分规则
- 模型输出整文件替换，不做增量合并；输出不可用时需人工介入
- 关键词检索对同义词不敏感，语料扩大后应升级为向量检索
- PowerContext 未配置推理模型，只做显式记忆写入，不做自动抽取
