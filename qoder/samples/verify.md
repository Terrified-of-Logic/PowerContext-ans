# 验证样例

按 `README.md` 跑通环境后，用下面 4 组用例自证。每组都给出**预期结果的判定特征**，
不要求 JSON 逐字相同（浮点距离允许 ±0.05 km 误差）。

服务启动后，直接在浏览器打开对应 URL 即可。

---

## 用例 1 · 关键词 + 空间（两路都命中）

**输入**

```
http://127.0.0.1:8000/api/search?q=水源&lat=30.521&lon=114.402&max_km=6&topk=3
```

**预期**

| 判定点 | 预期值 |
|---|---|
| 返回条数 | 3 |
| 第 1 条 `name` | `磨山南麓露营地` |
| 第 1 条 `dist_km` | 约 **2.43**（±0.05） |
| 第 1 条 `kw_hit` | 1 |
| 第 1 条 `reason` | 含「命中关键词 水源」和「距离」两个片段 |
| 全部条目 `dist_km` | 均 ≤ 6 |

**为什么它有说服力**：只有「磨山南麓露营地」的 note 里出现「水源」，
但它在地理上不是最近的（近的是南望山北坡剖面）。结果仍然排第 1，
说明**两路信号真的融合了**，不是单靠距离排序。

**实际结果**：见文末「实测记录」。

## 用例 2 · 只有关键词路（不给坐标）

**输入**

```
http://127.0.0.1:8000/api/search?q=剖面
```

**预期**

| 判定点 | 预期值 |
|---|---|
| 返回条数 | 5 |
| 全部 `kind` | 均为 `剖面` |
| `id` 顺序 | 1, 5, 8, 13, 14 |
| 全部 `dist_km` | 均为 `null`（没给坐标，不算距离） |

**为什么它有说服力**：`q=剖面` 命中的是**类型字段**，不是点位的名字。
说明检索覆盖了 `name` / `kind` / `note` 三个字段。

**实际结果**：见文末「实测记录」。

## 用例 4 · 硬约束（半径真的在过滤）

**输入**

```
http://127.0.0.1:8000/api/search?lat=30.521&lon=114.402&max_km=1
```

**预期**

| 判定点 | 预期值 |
|---|---|
| 返回条数 | 2 |
| `name` | `南望山北坡剖面`、`南望山东侧探槽` |
| `dist_km` | 分别约 **0.000** 与 **0.42** |
| 全部 `dist_km` | ≤ 1 |

**为什么它有说服力**：同一次查询把 `max_km` 从 6 改到 1，结果从 **9 条**收窄到 **2 条**。
说明**半径是硬过滤，不是排序权重**。

> 6 km 内的 9 条（半径放开时的完整候选）：
> 0.00 南望山北坡剖面 · 0.42 南望山东侧探槽 · 2.08 喻家山观景平台 ·
> 2.43 磨山南麓露营地 · 2.85 八分山防火道 · 3.99 马鞍山森林公园 ·
> 4.51 珞珈山西坡土壤点 · 5.10 东湖南岸芦苇荡 · 5.15 东湖西岸采样点

**实际结果**：见文末「实测记录」。

## 实测记录（2026-10-26 23:20）

**环境**：seekdb `5.7.25-OceanBase seekdb-v1.2.0.0`，经 `run.py init` / `run.py verify` 执行。
建表与插入 16 条均成功，说明 `schema.sql` 与 `app.py` 里的 SQL 在真实 seekdb 上可执行。

```
== 用例 0：记录条数 ==
  [PASS] records 共 16 条 实际 16

== 用例 1：关键词水源 + 6km 半径 ==
    南望山北坡剖面            0.00 km
    南望山东侧探槽            0.42 km
    喻家山观景平台            2.08 km
    磨山南麓露营地            2.43 km  含水源
    八分山防火道             2.85 km

== 用例 2：关键词剖面（不限半径）==
    命中 5 条（预期 5）

== 用例 3：无命中（温泉）==
    命中 0 条（预期 0）

== 用例 4：1km 硬过滤 ==
    桶内 2 条（预期 2）
    南望山北坡剖面            0.00 km
    南望山东侧探槽            0.42 km

全部通过
```

**验证到的东西**：

1. `ORDER BY t.dist_km IS NULL, t.dist_km ASC` 这种排序写法在 OceanBase 兼容模式下可执行
2. 距离计算全部在 SQL 表达式里完成，结果与手工计算一致（0.00 / 0.42 / 2.08 / 2.43 / 2.85）
3. 半径是硬过滤：从 9 条收窄到 2 条
4. 关键词只命中 `kind` / `name` / `note` 中真正含该词的点位，不是"查不到就全给"
