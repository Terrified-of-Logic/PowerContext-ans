# 服务器部署与运行

## 运行组成

Dify Cloud负责Code、LLM、HTTP节点编排；独立Linux服务器只运行记忆服务。使用Python 3.14.4、PowerContext 1.2.0及 `requirements-lock.txt` 中的锁定依赖。实际模型为Dify工作区的 `gpt-4o-mini`，OpenAI供应商插件1.0.8。服务器没有运行本地模型、Embedding或Rerank。

记忆服务入口：`https://8.148.13.142/midnight`。健康检查为 `/health`，账本接口为 `/recall`、`/commit`。除了健康检查与无密钥的DSL文件，读写请求均需要Bearer token。secret在Dify环境变量及服务器root-only文件中保存，不在参赛仓库中。

## 目录与服务

| 路径或单元 | 用途 |
|---|---|
| `/srv/midnight/app/service.py`、`game.py` | 与交付源码相同的服务及规则 |
| `/srv/midnight/venv` | 独立Python虚拟环境 |
| `/etc/midnight-memory.env` | `MIDNIGHT_TOKEN` 与 `MIDNIGHT_DATA`，权限600 |
| `/var/lib/midnight-memory` | PowerContext持久化数据库，由systemd管理权限 |
| `midnight-memory.service` | 开机自启，单worker，异常自动重启 |
| `/etc/nginx/conf.d/midnight-memory.conf` | 独立443反向代理，不替换原有80端口站点 |
| `/opt/midnight-certbot` | 独立Certbot 5.8.0环境 |
| `/etc/midnight-letsencrypt` | 本作品单独使用的IP证书和续期配置 |
| `midnight-certificate-renew.timer` | 每天两次检查续期，成功后校验并平滑重载Nginx |

systemd及Nginx配置模板见 `deploy/`。记忆服务使用DynamicUser和StateDirectory，只监听 `127.0.0.1:8765`；Nginx对外提供HTTPS。内存上限384MB、MemoryHigh为256MB、CPUQuota为50%。本次实际运行内存峰值约112MB；这不是负载测试结果或并发容量承诺。

## 在评审自己的环境中复现

1. 从参赛仓库取得本目录源码，准备Python 3.12或本次实测的3.14、Git与可访问依赖源的网络。
2. 创建独立虚拟环境，安装 `requirements-lock.txt`。PowerContext固定到官方提交 `9db1753434162c0aa7c9f1189a1722e617880a52`。如果在网络受限服务器安装，可在联网机器为目标平台下载锁定的预编译依赖后上传；PowerContext需从该提交构建，不能仅凭同名版本号替换为其他源码。
3. 按 `.env.example` 生成自己的随机 `MIDNIGHT_TOKEN`，至少24字符，设置独立数据目录。
4. 执行 `python -m uvicorn service:create_app --factory --host 127.0.0.1 --port 8765 --workers 1`。Dify和服务在同一可信网络时可使用内部地址；Dify Cloud需要公网可达且证书受信任的HTTPS入口。
5. 如使用systemd，按模板部署至 `/srv/midnight`，将环境变量写入 `/etc/midnight-memory.env`，设置权限600，然后执行 `systemctl daemon-reload` 与 `systemctl enable --now midnight-memory`。
6. 使用Nginx转发 `/midnight/` 到本地服务；域名证书或受支持的公网IP证书均可，保持TLS验证开启。模板的证书路径需要与自己的证书一致。
7. 在Dify导入 `midnight-ai-cloud-verified.yml`，设置 `memory_url`、secret类型的 `memory_token`，绑定工作区可用聊天模型。没有知识库、数据导入或作者原有存档依赖。
8. 执行 `验收样例.md`。新的用户身份会创建空账本；同一身份的“重新开局”会保留历史，含义与清空数据不同。

本次服务器的PowerContext wheel由固定提交构建，SHA256为 `1d0e09cb77bd77cd09ad7a6ce0288a129ed819d31711e068e4e1e3b0311bcb91`。该哈希用于核对本次部署产物；评审在其他构建环境重新构建时不要求逐字节相同。

## HTTPS与自动续期

已使用Let's Encrypt的shortlived profile取得公网IP证书。首次证书到期日为2026-11-02；后续到期日以服务器证书为准。2026-10-26的模拟续期成功，2026-10-27定时检查正常执行并确认尚未到续期时间。短期证书必须保持timer、80端口ACME验证路径及网络可用。

配置模板中的续期deploy-hook执行 `nginx -t` 后才重载，不停止现有HTTP站点。证书私钥、ACME账户材料及任何服务密钥均不随交付提供。

## 运维检查

```bash
systemctl status midnight-memory --no-pager
journalctl -u midnight-memory -n 30 --no-pager
systemctl list-timers midnight-certificate-renew.timer
curl --fail https://8.148.13.142/midnight/health
```

备份时应使用SQLite备份API或先停止**本作品服务**再复制整个数据目录，不能在服务运行时只复制主db而遗漏WAL。恢复后需要保留正确的StateDirectory权限。

Dockerfile/Compose作为另一种部署入口一并提供；本次实际验证的是systemd原生部署，未声称Docker镜像构建通过。
