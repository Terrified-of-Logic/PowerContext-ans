## 二、seekdb 数据库记录

### 表结构

```sql
CREATE TABLE IF NOT EXISTS ctx_docs (
  id        INT PRIMARY KEY AUTO_INCREMENT,
  path      VARCHAR(255) NOT NULL,
  kind      VARCHAR(20)  NOT NULL,
  heading   VARCHAR(255) NOT NULL DEFAULT '',
  symbol    VARCHAR(255) NOT NULL DEFAULT '',
  content   TEXT NOT NULL,
  KEY idx_kind (kind)
) ORGANIZATION = HEAP;
```

### 写入记录

```
$ node context/cli.mjs ingest
切分出 22 条： {"spec":10,"code":1,"test":11}
写入 seekdb：22 条
库内总条目：22
```

### 查询记录

```
$ node context/cli.mjs stats

按类型： {"spec":10,"code":1,"test":11}
```

上下文构造时的查询：

```sql
SELECT id, path, kind, heading, symbol, content FROM ctx_docs ORDER BY id;
```

取出 22 条后在 Node 侧打分排序，选出规格 3 条、代码 1 条、测试 3 条组装成上下文。
**检索结果直接决定了交给 MiniMax 的上下文内容**，不是装饰性写入。

### 规格更新同步验证

| 步骤 | 结果 |
|---|---|
| 修改 `specs/orders.md` 中 R1 的空字符串规则 | 改为「返回全部订单」 |
| 重新执行 `ingest` | 写入 22 条（覆盖） |
| 重新检索 | 输出为**修改后**的条文 |

说明上下文来自数据库实时检索，而非硬编码。验证后已还原规格并重新导入。

### 运行模式

支持两种连接方式：

- **嵌入式**（默认）：进程内启动 seekdb，数据落 `context/data/seekdb.db`
- **远程**：设置 `SEEKDB_REMOTE=1` 及 `SEEKDB_HOST/PORT/USER/PASSWORD/DB`，连接已有 seekdb 或 OceanBase

本次记录中的写入与查询在远程模式下执行；两种模式使用同一套 SQL。
