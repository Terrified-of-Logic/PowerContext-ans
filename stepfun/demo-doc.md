# seekdb 与端侧检索技术笔记

## 一、seekdb 是什么

seekdb 是面向 AI Agent 的一体化检索数据库，把向量、全文、结构化数据放在同一个引擎里。
它兼容 MySQL 协议，既可以作为嵌入式库在进程内启动，也可以作为单机服务或分布式集群运行。

嵌入式模式的价值在于：不需要单独部署服务，应用进程启动时顺带拉起数据库，
数据落在本地目录里，重启后仍然可用。

## 二、向量索引

seekdb 支持在表上声明 VECTOR 列，并为它建立 HNSW 向量索引。
建表语句大致如下：

```sql
CREATE TABLE docs (
  id INT PRIMARY KEY AUTO_INCREMENT,
  content TEXT,
  embedding VECTOR(512),
  VECTOR INDEX idx_vec (embedding) WITH (DISTANCE=l2, TYPE=hnsw, LIB=vsag)
) ORGANIZATION = HEAP;
```

建好之后，查询可以用 l2_distance 或 cosine_distance 计算距离，并按距离升序取前 K 条。
需要注意的是，某些受限实例（例如匿名试用环境）不允许创建 HNSW 索引，
这时应当降级为全表扫描，功能不受影响，只是数据量大时变慢。

## 三、混合检索

单纯的向量检索对专有名词不敏感，单纯的关键词检索又缺乏语义泛化能力。
混合检索把两路结果融合起来，常见做法是 RRF（Reciprocal Rank Fusion）：

```
score(d) = Σ 1 / (k + rank_i(d))     # k 通常取 60
```

RRF 的好处是不需要把两路分数归一化，对异常值也稳健。
实现上，向量路按距离排序，关键词路按命中次数排序，两路各自产出排名，
再用 RRF 求和得到最终顺序。

## 四、端侧推理

端侧推理指模型在用户设备上运行，而不是调用远程 API。
在浏览器里实现端侧推理，主流方案是 Transformers.js 配合 ONNX Runtime Web，
模型以 ONNX 格式下载到浏览器，用 WebAssembly 或 WebGPU 执行。

这样做有三个好处：数据不出本地、没有网络往返延迟、断网也能用。
代价是首次需要下载模型权重。

## 五、量化与性能

把模型量化到 8 位整数（q8）之后，权重体积大约缩小到原来的四分之一，
推理延迟也明显下降，精度损失通常很小，适合嵌入这类对精度不那么敏感的任务。

在浏览器里做向量化时，应当把推理放进 Web Worker，
否则会阻塞主线程，导致输入卡顿、页面失去响应。

## 六、实测数据

在本地环境测得：bge-small-zh-v1.5 的 q8 版本，单条文本向量化约 14 毫秒，
输出 512 维向量，两次无关文本的余弦相似度约 0.28。
模型从魔搭社区下载约 3 秒完成，之后走浏览器缓存，不再重复下载。
