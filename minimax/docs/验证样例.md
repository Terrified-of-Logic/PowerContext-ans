# 验证样例

本样例用于复现一次完整的「上下文检索 → 代码修改 → 测试验证 → 状态复用」流程。
按本文档的顺序执行，每一步都应得到「预期结果」一栏描述的输出。

---

## 一、任务描述

**任务 T1：为订单查询模块实现「按状态过滤」**

业务工程 `src/orders.js` 的 `queryOrders` 已实现金额过滤、排序、数量限制，
但规格中的 **R1（按状态过滤）尚未实现**。需要补上该功能，并保证既有行为不变。

明确指出两件事：

**要改什么**

- 文件：`business/src/orders.js`
- 符号：`queryOrders`
- 行为：`status` 有值时只返回 `status` 相等的订单；`status` 为空字符串时返回空数组；
  `status` 为 `undefined` 时不过滤

**哪些原有行为必须保持**

| 编号 | 行为 |
|---|---|
| R2 | 金额下限过滤，负值按 0 处理 |
| R3 | 按 `created_at` 倒序，无法解析的排最后 |
| R4 | `limit` 默认 20，上限 100，小于 1 返回空数组 |
| C1 | 函数签名不变 |
| C2 | 不得修改传入的数组 |

## 四、操作步骤

### 步骤 1：初始化索引

```bash
node context/cli.mjs ingest
```

**预期结果**

```
切分出 22 条： {"spec":10,"code":1,"test":11}
写入 seekdb：22 条
库内总条目：22
```

### 步骤 2：生成任务上下文

```bash
node context/cli.mjs context --task "实现按状态过滤：只返回指定状态的订单"
```

**预期结果** —— 输出中三部分来源必须齐全：

| 部分 | 应包含 |
|---|---|
| 一、适用的规格条目 | `R1 按状态过滤`（相关度最高）、`已知缺陷` |
| 二、需要修改的代码 | `src/orders.js`，符号 `queryOrders` |
| 三、用于验证的测试 | `R1 按状态过滤：只返回指定状态的订单` 排第一 |
| 四、任务当前状态 | 来自 PowerContext（首次为 0 条） |

### 步骤 3：记录改前测试基线

```bash
node business/test/orders.test.js
```

**预期结果**：`pass 9 / fail 2`，退出码 1。

### 步骤 4：交给 MiniMax 完成修改

```bash
node agent/run.mjs --task "实现按状态过滤：只返回指定状态的订单"
```

**预期结果**

```
[seekdb] 已写入 22 条，库内 22 条
[改前] 测试 失败
[MiniMax] 返回 N 字符，耗时 XXXXms
[应用] 已写入业务代码
[改后] 测试 通过
[PowerContext] 已记录任务状态
```

产物目录 `agent/runs/<时间戳>/` 下应有：
`context.md`、`prompt.md`、`response.md`、`usage.json`、`patched-orders.js`、
`orders.before.js`、`test-before.log`、`test-after.log`。

### 步骤 5：确认修改有效

```bash
node business/test/orders.test.js
```

**预期结果**：`pass 11 / fail 0`，退出码 0。

### 步骤 6：验证状态可以复用

```bash
# 停掉 PowerContext 服务，再重新启动
powercontext server run --env-file ../powercontext/.env

# 读回
node context/cli.mjs status
```

**预期结果**：仍能列出步骤 4 写入的任务记录，包含「改前测试失败 / 改后测试通过 / 上下文条数 / 耗时」。

### 步骤 7：验证规格变更会影响输出

```bash
# 修改 specs/orders.md 中 R1 的条文，例如把「返回空数组」改成别的处理方式
node context/cli.mjs ingest
node context/cli.mjs context --task "状态为空字符串时怎么处理"
```

**预期结果**：输出中的规格条文是**修改后**的内容，不是旧版本——说明上下文来自数据库检索，
而不是硬编码的固定答案。

## 六、重置方法

把环境恢复到初始状态：

```bash
# 1. 还原业务代码
cp agent/runs/<最早那次>/orders.before.js business/src/orders.js
# 或者用 git 还原：git checkout -- business/src/orders.js

# 2. 清空检索索引（删掉 seekdb 数据目录）
rm -rf context/data

# 3. 清空运行记录
rm -rf agent/runs

# 4. 确认基线
node business/test/orders.test.js    # 应回到 pass 9 / fail 2
```

PowerContext 的数据在 SQLite 文件里，如需清空，删除其配置目录下的 `*.db` 后重启服务。

**注意**：重置只会还原代码与索引，`business/test/orders.test.js` 本身不应修改。
测试集在修改前后必须保持一致，不得通过删除断言、跳过用例或修改预期结果来让测试通过。
